# V1.1 Security and Privacy Readiness Checklist

This is an engineering release checklist, not a legal opinion or security certification. The prior `qa-audit-report.md` contains the static security observations. Confirm each item in the deployed environment before launch.

## Engineering security

- [ ] Release artifact uses a dedicated signing key held outside source control; debug signing is not used.
- [ ] Run integration checks with two separate businesses and attempt cross-tenant reads, mutations, exports and identifier substitution for every endpoint.
- [ ] Verify owner, manager, cashier and storekeeper permissions at the API boundary, including direct requests that bypass the UI.
- [ ] Verify access-token expiry, refresh-token rotation/reuse behavior, logout cleanup and session revocation.
- [ ] Confirm production HTTPS, strict CORS, strong secret management, shared rate limiting and safe error responses.
- [ ] Validate upload type, size and content; reject CSV formula injection and unexpected file data.
- [ ] Audit high-impact stock, payment, role and export actions; verify logs contain enough actor/context data without exposing secrets.
- [ ] Run migration and backup/restore rehearsal; validate migration rollback/forward plan.
- [ ] Configure monitoring and an incident-response owner and contact channel.
- [ ] Review third-party packages and document patch/update ownership.

## Kenya data-protection review

- [ ] A qualified Kenyan lawyer reviews the privacy policy, terms, consent language and actual data flows.
- [ ] Operator legal identity, support contact, data-protection contact and complaint path are published.
- [ ] Document each data category, purpose, lawful basis, retention rule and authorized recipients.
- [ ] Confirm data minimization and that customer information is entered only with the merchant’s authority.
- [ ] Inventory hosting, database, notification and support processors, processing countries and transfer safeguards.
- [ ] Publish access, correction, deletion, objection and complaint request procedures and response ownership.
- [ ] Set account deletion and backup purge timelines; test the deletion request process.
- [ ] Review whether registration consent is required and ensure withdrawal/consent records are handled appropriately.
- [ ] Keep marketing notifications disabled until separate explicit opt-in is implemented and recorded.
- [ ] Define incident assessment, escalation and notification steps with legal counsel.

**Do not describe StockPesa as legally compliant until implementation, operational practice and policy are reviewed by qualified Kenyan counsel.**
